# 云州档案 · ArcSync

云州档案服务中心的档案检索与查阅协同平台。项目以公开档案试点为范围，支持「申请 → 权限核验 → 检索 → 卷页核对 → 审核 → 交付」的本地演示。典型事件是更正件未关联原卷导致旧版误命中，整理员发现冲突后暂停建议并交审核员复核。

**当前版本支持接入对话模型、嵌入模型、FAISS 和 MySQL。默认使用合成档案，模型需单独配置。** 原始需求来自合成访谈，真实接入、授权与验收口径仍需业务确认。

一键启动使用本地演示配置。生产部署按 [生产部署说明](docs-archive/production-phase1.md) 和 [上线前检查清单](docs-archive/prelaunch-checklist.md) 验证目标环境。

## 快速运行

### 完整版

macOS 双击项目根目录的 **[启动项目.command](启动项目.command)**，自动检查 Python、创建独立环境、按需安装依赖、启动服务并打开浏览器。首次运行需要 Python 3.11+，缺少依赖时需要联网；依赖齐全后可离线启动。

也可在项目目录执行同一个一键启动流程：

```sh
sh scripts/start.sh
```

请保留启动窗口，按 `Ctrl+C` 停止服务。重复启动会打开已运行的平台；端口被其他程序占用时会提示更换，不会关闭其他程序。

只检查并准备环境：`sh scripts/start.sh --check`。不自动打开浏览器：`sh scripts/start.sh --no-browser`。

浏览器打开 **http://127.0.0.1:8765**。欢迎页输入账号后自动进入对应端，演示密码为 **`ArcSync2026!`**。

前端不依赖外部字体、图片或 CDN。数据持久化在 `data/arcsync.sqlite3`，重启后保留。

可选：已安装 Node 时，`npm start` 启动，`npm test` 验证，`npm run build` 打包；无需 `npm install`。

自定义端口：

```sh
PORT=8877 sh scripts/start.sh
```

首次初始化时可通过 `ARCSYNC_DEMO_PASSWORD` 指定演示口令。该环境变量只影响新建账号，不能修改已有数据库内账号。用 `ARCSYNC_DB` 指定另一份数据库可创建独立演示环境。

### 独立 MVP

MVP 用于演示公开档案查阅的三岗位闭环，使用合成档案和独立 SQLite 数据库，无需配置模型。已准备 `.venv` 时，在仓库根目录运行：

```sh
PYTHONPATH=src .venv/bin/python -m mvp
```

打开 [本机 MVP](http://127.0.0.1:8766/)，选择业务查询代表、档案整理员或查阅审核员，使用密码 `ArcSync2026!` 登录。数据库位于 `data/mvp/arcsync.sqlite3`。首次环境准备与完整演示步骤见 [MVP 使用说明](src/mvp/README.md)。

## 多轮档案智能查阅

登录后点击侧栏“智能查阅”，或打开 `/chat-ui`。支持SSE逐字回答、文件名和条文片段引用、最近6轮完整上下文、会话恢复与停止生成。聊天保存在SQLite，按独立user_id隔离。接口为 `POST /chat`，详细协议、错误码和独立账号创建方法见 [聊天接口与使用说明](docs-archive/chat-api.md)。

旧演示账号可继续登录；不同员工应创建不同用户名，不能共用同一个演示账号来实现人员隔离。升级后请重新登录。模型未配置时明确提示，已有聊天仍可查看。

## 配置智能查阅

复制 `.env.example` 为 `.env`，填写对话模型与嵌入模型的地址、名称、密钥，再重新启动。支持 Ollama 本地服务、vLLM 服务和兼容协议的云端 API；不自动下载模型。默认未配置时，页面明确提示，不用固定回答模拟 AI。

两端都有“智能查阅”；后台“模型与知识”提供连接检查和资料页文本导入。FAISS 按授权资料构建索引，向量缓存保存到业务库。默认保留原 SQLite；配置 MySQL URL 后切换，可用显式迁移脚本复制到空库，详细说明见配置指南。

## 已实现

- 工作台：责任待办、待接手交接、异常提醒、连接及快照状态。
- 查阅业务：创建申请、公开试点权限核验、业务台账、随单草稿与事件时间线。
- 档案检索：按关键词、类别、年度、状态查询授权目录，查看资料版本与更正关系。
- 卷页核对：合成卷页阅读器、扫描页与纸质页映射、人工确认引用、资料版本绑定。
- 审核交付：确认接手、提交审核、审核通过或说明原因退回、记录人工交付、导出文本记录。
- 异常处理：暂停建议、审核员分派、实际岗位填写处理结果、审核复核恢复。
- 服务反馈：关联业务与资料版本登记，由审核员核对。
- 管理审计：六岗位服务端鉴权、审计追加记录、试点暂停、保护专员复盘恢复。
- 试点评估：真实数据库中的流程计数和原始事件；不伪造定位提速、准确率或零泄露结论。

## 走通一笔业务

1. 以 **林亦舟 / 档案整理员** 登录；打开「档案检索」。
2. 检索「总体规划」，打开有效资料或后续更正文件。过时与待修复资料不能直接加入依据。
3. 打开卷页，核对页码；选择「县城总体规划批复查阅」，勾选人工确认后加入业务依据。有后续更正时还须确认更正核对。
4. 在「查阅业务」打开该业务，填写随单说明，点击「提交审核」，填写交接说明。
5. 右上角退出并更换账号，以 **reviewer / 唐映秋（查阅审核员）** 登录管理后台；在「审核与交接」确认接手。
6. 打开业务，填写审核依据并通过，再记录人工交付，可导出带引用信息的合成交付记录。
7. 另一条路径：发现页码或版本问题时转人工；审核员分派，切换实际处理岗位填写结果，再由审核员确认接手并复核恢复。

新建申请从「待权限核验」开始：审核员核验公开试点范围后，整理员须先确认接手才能定位。退回与异常跨岗恢复也须确认接手。

完整的逐步测试流程、示例填写内容、预期状态与执行记录模板见 [完整闭环测试操作手册](docs-archive/end-to-end-test-guide.md)。

发现版本冲突或更正依据缺失时，暂停建议并交审核员复核。补齐依据后重新核对版本和卷页，再继续送审。见 [原业务现状图](docs/流程图一-业务现状.png) 和 [目标流程图](docs/流程图二-目标流程与旧版误命中.svg)。

## 验证与交付

在项目的 Python 环境中安装测试依赖。已用启动脚本创建 `.venv` 时，安装和测试都使用该环境。

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
sh scripts/test.sh
sh scripts/build.sh
```

测试覆盖完整流程、跨岗接手、越权读取与写入、页码与版本拦截、暂停、冲突编辑、异常复核、反馈和数据库持久化。开发依赖包含 Redis Lua 契约测试所需的 `fakeredis[lua]`。HTTP 测试需要允许绑定本地临时端口。

交付包位于 `dist/arcsync-0.3.0.zip`，不含数据库、会话和环境口令。CI 运行同样的验证与构建。

## 当前边界

本地服务默认监听 `127.0.0.1`。外部档案库、OCR、授权审核台和真实 SSO 尚未接入。关键词检索使用目录与固定摘要，卷页由合成模板生成。没有对原系统回写或档案删除接口。

暂未实现真实定时同步、断线重连补齐、生产级不可篡改审计、留存到期审批任务和 SLA 自动升级。内置 30 条用例使用合成档案，其结果用于验证当前实现，不代表真实档案试点的准确率。后续见 [部署说明](docs-archive/deployment.md)。

本次建设范围与验收条件见 [系统需求分析方案](docs/系统需求分析方案.docx) 和 [详细项目设计方案](docs/详细项目设计方案.docx)。已有实现的接口与验证记录见 [接口文档](docs-archive/api.md) 和 [交付验证记录](docs-archive/verification.md)。

本项目代码采用 MIT 许可证，第三方或真实档案的使用权限需另行取得。

### 制度与问答管理后台

管理员登录后在侧栏进入“制度与问答管理”（`/admin/manage`），支持 Markdown/PDF 上传并向量化、数据库提示词即时更新、按人员与时间审计问答及人工标记疑似越权查阅／异常利用线索。详见 [管理后台说明](docs-archive/admin-workspace.md) 和 [默认系统提示词](docs-archive/default-system-prompt.md)。

智能体可自主检索、读取卷页、核对更正关系、收集查阅需求，并在服务端校验通过后创建申请草稿。Agent创建前会流式展示具体草稿并暂停，员工确认后才保存；草稿在 `/access-drafts` 人工确认提交，进入原有“待权限核验”流程。工具约束与接口见 [档案智能体设计与使用](docs-archive/autonomous-agent.md)。

Agent使用项目内轻量Harness，最多5轮模型决策，逐轮记录工具参数、耗时和结果摘要，支持创建前人工中断与持久化恢复。三个档案场景预期轨迹及阶段5日志分析见 [Harness编排说明](docs-archive/agent-harness.md)。

### 生产安全与成本控制（第一阶段）

生产模式增加默认账号阻断、对象权限过滤、Redis共享限流与模型预算预留、模型用量管理页、就绪检查，以及容器部署和备份/回滚工具。默认一键启动仍为开发模式。部署步骤、预算口径和验证边界见 [第一阶段生产部署说明](docs-archive/production-phase1.md)。真实环境验收前不要直接映射开发服务到公网。

### 自动评测与版本对比（第二阶段）

管理后台“项目评测”支持30条云州档案用例的隔离排队执行、多轮上下文、工具/引用自动检查、独立人工复核、报告下载与版本对比。完整30项通过后才可进入发布审批；正式发布脚本校验数据库中的评测证据。真实模型执行会产生费用，未配置时不会生成模拟成绩。步骤及边界见 [评测平台说明](docs-archive/evaluation-platform.md)。
