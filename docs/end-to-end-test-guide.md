## 1. 本次测试要走通什么

按以下顺序完成一笔新建业务。主流程中的异常与退回均为有意设计的测试动作，须在记录中注明“闭环测试”，不代表真实资料已经修复或真实审核发现问题。

```text
查询代表创建申请
  → 审核员核验公开试点权限
  → 整理员确认接手
  → 检查歧义资料并转人工
  → 审核员分派给工程师
  → 工程师填写处理结果
  → 审核员确认接手并复核恢复
  → 整理员确认接手、核对有效引用并提交审核
  → 审核员确认接手、退回补充说明
  → 整理员确认接手、重新确认引用并再次提交
  → 审核员确认接手、审核通过并记录交付
  → 查询代表登记反馈
  → 审核员核对反馈
  → 保护专员核对审计，检查数据保留
```

**始终区分两个概念：**“业务状态”表示处理到哪一步，“当前责任岗位”表示谁仍负责。生成交接记录后，须由目标岗位点击“确认接手”，业务责任才转移。异常的“实际处理岗位”可以是工程师，不等于整笔业务已经转交给工程师。

## 2. 测试前准备

### 2.1 打开系统

1. 在浏览器打开 [本地平台](http://127.0.0.1:8765)。
2. 若打不开，在项目文件夹中启动服务：

   ```sh
   sh scripts/start.sh
   ```

3. 确认没有“试点已暂停”的横幅。若已暂停，由保护专员核实原因后恢复，再开始主流程。
4. 若出现“数据暂未更新”，记录该状态。可由工程师在“管理与审计”点击“刷新本地合成快照”；这只刷新本地演示快照，不代表真实系统同步成功。
5. 全程使用同一个浏览器标签页。各岗位切换后重新进入本笔业务，避免操作到其他样例。

无需删除或重置原数据库，也不要更改已有业务来凑测试状态。

## 3. 主流程：逐步操作与预期结果

### 阶段一：申请、权限核验与接手

**步骤 01｜叶书创建独立申请**

1. 以“叶书 · 业务查询代表”登录。
2. 打开“查阅业务”，点击“新建查阅申请”。
3. 填写第 2.3 节的查阅事项、申请单位、用途。
4. 点击“创建并提交权限核验”。
5. 在业务详情记录系统生成的业务编号。

预期结果：业务状态为“待权限核验”，当前责任为“唐映秋 · 查阅审核员”；处理时间线包含“创建查阅申请”。

证据：保存一张显示事项、业务编号、状态与责任人的截图。

**步骤 02｜唐映秋核验公开试点权限**

1. 切换为“唐映秋 · 查阅审核员”。
2. 打开本笔业务，点击“核验试点权限”。
3. 核验范围选择“公开档案试点”，点击“确认权限并交接”。

预期结果：业务状态变为“定位中”；生成交给整理员的“待接手”记录；**此时当前责任仍为唐映秋**，不能仅因状态变为定位中就判定交接完成。

**步骤 03｜林亦舟确认接手并保存草稿**

1. 切换为“林亦舟 · 档案整理员”。
2. 在“审核与交接”的“待我确认接手”找到本笔业务，点击“确认接手”。也可在业务详情顶部确认接手。
3. 打开业务详情，检查当前责任已变为林亦舟。
4. 在“关键说明 / 待确认事项”填写：

   > 闭环测试：先排除歧义资料，再核对规划批复与后续调整；最终引用须保留档号、版本和双页码。

5. 点击“保存草稿”，等待成功提示；刷新页面后重新打开本笔业务。

预期结果：业务仍为“定位中”；交接为“已接手”；草稿刷新后保留；时间线包含“确认接手”。

### 阶段二：异常转人工、处理与恢复

**步骤 04｜林亦舟查看待修复卷页并触发异常**

1. 打开“档案检索”，输入 `YZ-CJ-1987-009`，点击“检索”。
2. 打开“县城规划用地登记表及说明”。
3. 检查状态为“待修复”，纸质页码为待核对，“确认并加入业务依据”不可用。
4. 点击阅读器中的“暂停建议 · 转人工”。
5. **在弹窗的“关联查阅业务”中明确选择本笔新建业务**，不要使用默认选中的其他业务。
6. 异常类型选择“页码映射异常”；原因填写：

   > 闭环测试：YZ-CJ-1987-009 的扫描页与纸质页映射存在歧义，不能作为引用依据，请人工核对并建议替代资料。

7. 点击“记录异常并转人工”。

预期结果：本笔业务变为“异常处理中”；“异常与修复”新增一项“待分派”异常，关联上述档号及本笔业务；该资料未出现在已确认引用中。记录异常编号。

说明：应从卷页阅读器发起本步骤，这样异常才带关联档号；从业务详情发起的异常属于业务级异常，档号可为空。

**步骤 05｜唐映秋分派给工程师**

1. 切换为唐映秋，打开“异常与修复”。
2. 按本笔业务编号和异常编号找到刚创建的异常，避免选中预置异常。
3. 点击“分派处理人”，选择“档案系统工程师 · 秦芮”。
4. 分派说明填写：

   > 闭环测试：请核对页码歧义，记录处理依据；不要修改原档案或直接解除质量标记。

5. 保存分派。

预期结果：异常状态变为“待处理”，实际处理岗位为秦芮；业务仍为“异常处理中”。分派异常处理岗位不等于已转移整笔业务责任。

**步骤 06｜秦芮记录处理结果**

1. 切换为“秦芮 · 档案系统工程师”。
2. 打开“异常与修复”，找到本笔异常，点击“填写处理结果”。
3. 填写：

   > 闭环测试：已记录页码映射歧义。本轮不修复源档案，继续排除 YZ-CJ-1987-009，建议改用有效的规划批复及后续调整文件。源资料仍保留待修复状态。

4. 点击“保存并提交复核”。

预期结果：异常变为“已处理”；本笔业务变为“待复核”；生成交审核员的待接手记录；原档案仍为“待修复”。**异常已处理不等于源数据已修复，也不等于业务已恢复。**

**步骤 07｜唐映秋接手并复核恢复**

1. 切换为唐映秋，在“审核与交接”确认接手本笔业务。
2. 打开本笔业务，点击“复核后恢复定位”。
3. 复核依据填写：

   > 闭环测试：确认歧义资料仍被排除，异常处理说明完整；允许重新定位有效资料，不认可源档案已经修复。

4. 点击“恢复并交整理员接手”。

预期结果：业务变为“定位中”，生成交林亦舟的待接手记录；林亦舟接手前，当前责任仍为唐映秋。

**步骤 08｜林亦舟接手恢复后的业务**

1. 切换为林亦舟，在“审核与交接”确认接手。
2. 打开本笔业务，核对状态、责任、草稿及异常处理时间线。

预期结果：业务为“定位中”，当前责任为林亦舟；草稿保留，异常记录可追溯，没有把歧义卷页加入引用。

### 阶段三：更正核对、引用与首次提交

**步骤 09｜检查过时资料不能直接引用**

1. 以林亦舟身份检索 `YZ-CJ-1985-017`。
2. 打开卷页，查看“已更正”状态与后续文件提示。
3. 检查“确认并加入业务依据”不可用，随后关闭阅读器。

预期结果：过时资料可在授权范围查看，但不能被直接加入本笔业务的引用依据。

**步骤 10｜核对更正关系并加入两条有效引用**

1. 检索 `YZ-CJ-1986-001`，打开卷页。
2. 核对标题、档号、v2.0，以及扫描第 6 页 → 纸质第 6 页。
3. 查看后续更正 `YZ-CJ-1988-003`，点击“查看更正文件”，阅读其内容与适用说明。
4. 关闭后重新检索并打开 `YZ-CJ-1986-001` 第 6 页。当前版本点击更正文件会切换阅读器，不提供原页返回按钮，因此须重新打开。
5. 关联业务选择本笔业务，勾选“我已核对本页内容、资料版本与纸质页码”和“我已阅读后续更正，确认此引用的适用范围”。
6. 点击“确认并加入业务依据”。
7. 再检索 `YZ-CJ-1988-003`，打开扫描第 6 页，确认纸质第 30 页及 v1.0。
8. 选择本笔业务，勾选人工确认，加入第二条引用。

预期结果：本笔业务有两条有效引用，分别绑定上述档号、版本和双页码，记录确认人为林亦舟。前一条可看到已核对更正关系。

可在未勾选必填确认框时尝试提交，预期表单阻止提交，不新增引用。不要把勾选框视为系统自动验证真实业务适用性的证明。

**步骤 11｜提交审核并核查接手边界**

1. 打开本笔业务详情，检查两条引用和原先草稿。
2. 点击“提交审核”。交接说明填写：

   > 闭环测试：已排除待修复资料，已核对规划批复及后续调整，共两条引用；请审核适用范围与对外引用表述。

3. 点击“提交并等待接手”。
4. 此时不要另外点击“发起责任交接”，提交审核已经自动生成交接记录。

预期结果：业务为“待审核”，交接为“待接手”，当前责任仍为林亦舟；不能将发送交接的动作记作审核完成。

### 阶段四：审核退回、重新确认与再次提交

**步骤 12｜唐映秋接手后故意退回一次**

1. 切换为唐映秋，先确认接手本笔业务。
2. 打开业务详情，检查当前责任已变为唐映秋，审核操作可见。
3. 点击“退回定位”，填写：

   > 闭环测试：请在随单说明中明确本次最终答复依据为后续调整文件，并重新确认最终引用。

4. 点击“确认退回”。

预期结果：业务回到“定位中”；退回原因可见；两条旧引用被清空，不能直接沿用；生成交整理员的待接手记录。人工确认与退回历史仍留在时间线中。

**步骤 13｜林亦舟接手、补充草稿并重新确认最终引用**

1. 切换为林亦舟，确认接手本笔业务。
2. 将随单说明补充为：

   > 闭环测试：已按退回意见补充。本次最终答复采用 YZ-CJ-1988-003 / v1.0，扫描第 6 页、纸质第 30 页；此前批复用于沿革核对，歧义资料继续排除。

3. 保存草稿。
4. 检索 `YZ-CJ-1988-003`，打开扫描第 6 页，核对纸质第 30 页。
5. 选择本笔业务，勾选人工确认并加入依据。
6. 回到本笔业务，确认仅有这一条最终引用。

预期结果：草稿更新，引用数为 1；退回原因与旧处理记录保留；新确认引用绑定 v1.0 和纸质第 30 页。

**步骤 14｜再次提交并由审核员接手**

1. 林亦舟点击“提交审核”，填写：

   > 闭环测试：已补充最终适用依据并重新确认引用，请复审 YZ-CJ-1988-003 / v1.0 / 纸质第 30 页。

2. 点击“提交并等待接手”。
3. 切换为唐映秋，确认接手本笔业务。

预期结果：业务为“待审核”，当前责任为唐映秋；第一次与第二次审核交接均有独立记录，不重复新增业务。

### 阶段五：审核通过、交付与导出

**步骤 15｜唐映秋审核通过**

1. 检查最终引用只有 `YZ-CJ-1988-003 / v1.0 / 扫描第 6 页 / 纸质第 30 页`。
2. 检查本笔异常均已处理，草稿已补充适用说明。
3. 点击“审核通过”，审核依据填写：

   > 闭环测试：公开试点范围、资料版本、纸质页码与适用说明已核对；最终引用采用后续调整文件，人工审核通过。

4. 点击“确认审核通过”。

预期结果：业务变为“待交付”，时间线记录审核人、时间与审核说明。**审核通过尚不等于已经交付。**

**步骤 16｜唐映秋记录人工交付并导出**

1. 点击“记录人工交付”。
2. 交付说明填写：

   > 闭环测试：已向闭环测试研究组（合成）交付公开资料引用记录，范围限 YZ-CJ-1988-003 / v1.0 / 纸质第 30 页，不包含受限资料。

3. 点击“确认已人工交付”。
4. 点击“导出交付记录”，打开下载的文本文件。

以下不改变主流程通过条件，执行时单独记录结果。暂停是全局操作，先确认没有其他人在进行演示，完成后恢复。

### 5.1 资料权限检查

1. 以林亦舟检索 `YZ-R-1991-002`，预期无结果，不显示受限测试资料正文。

3. 切换顾明岚，用相同条件检索，预期仍无结果；主任的管理权限不扩大档案读取范围。

这些界面检查只能证明所执行路径的表现，不能单独证明不存在任何越权路径；服务端直接访问和写入拦截另由自动测试覆盖。

### 5.2 试点暂停与恢复检查

1. 先记录当前“试点评估”的业务计数，避免把补充测试新增业务算入主流程的计数断言。

## 6. 失败处理与常见问题

| 现象 | 排查与处理 |
| --- | --- |
| 找不到本笔业务 | 清除业务筛选，按实际生成的业务编号查找；不要使用预置编号代替 |
| 检索没有结果 | 清除类别、年度、资料状态筛选，再输入完整档号 |
| 引用按钮不可用 | 检查是否为整理员、是否已确认接手、业务是否定位中、资料是否有效、试点是否暂停 |
| 阅读器选中了其他业务 | 在“关联查阅业务”中手动选择本次带唯一标记的业务后再确认 |
| 不能审核、恢复或交付 | 先核对当前岗位、责任人、交接是否已接手，以及当前业务状态 |
| 提示“记录已更新，请刷新后重试” | 先复制尚未保存的文字，再刷新业务数据，核对最新状态后重新操作 |
| 异常处理后仍不能直接定位 | 工程师处理不等于恢复；审核员须先接手并复核恢复，再由整理员接手 |
| 修复队列显示已处理，但档案仍待修复 | 本测试只记录处置意见，不修改源档案；这是预期结果 |
| 退回后旧引用不见了 | 这是预期行为；重新打开有效卷页并确认最终引用 |
| 交付后不能修改草稿 | 这是预期行为；后续疑问通过“服务反馈”关联原业务核对 |
| 快照出现待刷新提示 | 记录提示；工程师可刷新本地合成快照，不能据此宣称真实系统已同步 |
| 暂停后无法继续主流程 | 由保护专员确认原因并记录复盘恢复；不要绕过暂停条件 |
| 导出文件未出现 | 查看浏览器下载列表及下载提示，确认允许本次下载；再核对业务是否已交付 |

任一实际结果与预期不符：记录步骤编号、岗位、业务编号、实际状态、错误提示与截图；不通过直接改数据库、清空审计或跳过接手来继续。阻塞关键流转时，本轮记为“阻塞”，修复后用新标记重测，并保留原证据。
