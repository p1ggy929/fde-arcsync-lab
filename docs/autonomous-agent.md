# 云州档案自主查阅智能体

在原有模型、FAISS、JWT、聊天和人工协同基础上升级。取消固定“意图分类→预先检索”，模型每轮自行决定检索、读取、更正核对、收集申请信息、查询状态或追问。没有可用工具证据时可以追问，不能编造档案事实。

## 使用

1. 登录后进入“智能查阅”(`/chat-ui`)，描述查阅目的、申请单位、档案范围及利用方式。
2. Agent 检索和读取授权资料；只有目录摘要或页码有歧义时不能通过申请草稿校验。当前演示目录不代表已导入真实正文，需先由工程师导入页文本。
3. 需要生成草稿时，用户勾选“允许本次创建查阅申请草稿”并发送。授权只在本次请求内有效，发送后复位；仅创建草稿，不自动提交。
4. 打开“申请草稿”(`/access-drafts`)核对内容，点击“确认内容并提交权限核验”，进入原有待权限核验→接手→定位与人工确认引用→审核→人工交付流程。候选范围存为随单说明，不写入人工已确认引用。
5. 校验凭证15分钟有效；过期后在聊天中重新读取、核验和校验，然后再次请求创建，刷新同一草稿凭证而不重复建单。

## Function Calling

所有参数采用Pydantic严格类型，拒绝额外字段，字符串去首尾空白。发布schema使用`strict: true`、`additionalProperties: false`，所有属性必填，可空参数以null表达。身份、岗位及本次草稿授权均由服务端注入，模型不能传入“已批准”“校验通过”等覆盖字段。

| 工具 | 参数 | 作用与约束 |
|---|---|---|
| search_archives | query, limit(1–8), category, year(可空) | 授权且有效的资料中混合检索 |
| read_archive_page | document_id, scan_page | 读取页文本；目录摘要不会产生页读取凭证 |
| check_archive_validity | document_id, version | 核对当前版本、状态、更正链；循环或异常拒绝 |
| get_access_case | case_id(可空) | 读取本人事项；null列出最近20项，支持跨轮继续 |
| update_access_case | case_id(可空), revision, title, applicant, purpose, usage, archives | 完整替换事项；archives元素含document_id/version/scan_page。新建revision=0，修改须匹配当前版本；修改版本递增 |
| validate_access_request | case_id, revision | 校验信息、公开试点范围、页码、读取和更正核对结果；通过后签发服务端随机凭证 |
| create_access_draft | case_id, revision, validation_id | 只在用户授权且凭证有效时创建草稿；不提交、不审批 |
| get_business_status | business_id | 管理岗位可查业务；员工只可查本人创建的业务，演示样例按当前责任岗位可见 |
| get_access_rules | 无 | 获取固定平台流程事实，供流程回答引用 |

## 顺序与防绕过

`search_archives`和信息收集可自由安排。`validate_access_request`必须在选定页已读取、有效性已检查、后续更正正文已读取、事项信息完整后通过。需要明确区分机器读取与人工卷页确认。

凭证绑定员工、事项版本及完整档案/正文/页码/更正关系快照，15分钟过期。只有passed返回validation_id。needs_input、needs_review及工具错误均不产生凭证。

`create_access_draft`同时受动态工具列表和执行器约束：未授权或没有有效凭证时不提供该工具；伪造工具调用仍在服务端被拒绝。建单必须独占一轮，不能与校验或其他工具放在同一轮执行。服务端在事务中重新读取当前事项及档案快照，凭证过期、人员不符、版本/权限/正文/映射变化均拒绝。账号登录态和平台暂停状态仍按原有机制复查。

事务及(case_id,revision)唯一约束确保并发重复调用只产生一份草稿。草稿页面显示创建时内容；事项变更后旧草稿失效。用户提交草稿时再核验，正式业务创建和草稿绑定共用事务；重复提交返回同一业务编号。用户确认是提交到人工权限核验，不是开放批准。

## 存储及审计

业务数据库（SQLite/MySQL）新增access_cases、access_validations、access_drafts、business_requesters、agent_tool_audit。启动时增量建表，不删除原业务。离线迁移工具包含新增表；登录会话与JWT签名密钥仍不复制。

工具执行（含前置条件拒绝）记录run_id、具名user_id、工具、参数、结果及时间，多轮聊天也记录。管理员在对话审计页按员工和时间查看最近50条工具记录，或调用GET /api/admin/agent-tools查看最近100条。校验通过/拒绝、草稿创建及人工提交另写原有操作审计。不记录模型隐藏思考。

业务提示词从数据库读取。仅当内容与旧报销默认模板完全相同时自动迁移到档案默认模板；自定义模板不覆盖。系统附加不可被业务模板解除的执行说明，但最终权限和前置条件由代码实现，提示词不是授权依据。

## HTTP

- GET /api/access-cases：本人最近事项。
- GET /api/access-drafts：本人草稿与创建时内容。
- POST /api/access-drafts/{id}/submit：人工提交；JSON `{}`及X-ArcSync-Request: 1。
- POST /chat 或 /api/agent/chat/stream：可选allow_draft布尔值，默认false；由用户明确授权，非模型工具参数。

## 验证边界

自动测试使用真实临时数据库、FAISS和协议/模型替身，覆盖自主选工具、即时模板、跨员工访问拒绝、缺少校验、并行校验建单拒绝、伪造参数、版本/权限/正文/页码变化、后续更正、过期凭证续验、并发幂等和人工提交。浏览器验证使用独立临时库，确认草稿提交进入待权限核验且人工确认引用仍为空。

尚未使用真实生产档案或真实模型推理验证任务成功率。实际使用需要配置支持工具调用的模型及嵌入服务，导入可用页文本；受限档案及正文质量异常仍转人工。执行预算为10轮、20次工具、12条来源，保留原聊天总时限。
