# 授权与人工边界

- 账号按六个演示岗位配置；使用 PBKDF2-HMAC-SHA256 哈希和随机盐保存演示口令。
- 登录后生成 8 小时随机会话，Cookie 使用 HttpOnly、SameSite=Strict；本地 HTTP 不设置 Secure，生产必须通过 HTTPS 配置。
- JSON 写请求要求自定义同源请求头，浏览器跨源请求被拒绝，不开放 CORS。
- 公开档案可由已登录演示岗位查询；受限测试档案只对保护专员返回。目录查询、原卷页接口和直接档号访问均校验。
- 所有试点业务属于公开档案范围。即使保护专员拥有受限资料阅读权，也不得把该资料关联到公开业务的异常与依据。
- 全局审计只向主任与保护专员返回。主任看到的专员操作细节脱敏，不通过管理权限获得受限档案信息。
- 业务状态更改既检查岗位也检查当前责任；仅向前端隐藏按钮不构成授权控制。
- 分派只指派异常实际处理岗位，不静默完成责任交接。跨岗复核与恢复仍须接手确认。
- 主任和保护专员可暂停试点，仅保护专员可记录复盘后恢复。暂停期间正常流程推进被拒绝；草稿及人工异常处理可继续。
- 演示不提供开放受限资料、改变密级、销毁档案或回写源系统的接口。

此权限矩阵为演示实现，并非真实组织制度。生产需接入 SSO、具名用户授权、业务范围、访问撤销、限流、传输与静态加密，以及专用安全评估。

SQLite 触发器只能约束应用侧审计修改；有数据库文件管理权的人仍可能更改数据，因此不宣称生产级不可篡改。
