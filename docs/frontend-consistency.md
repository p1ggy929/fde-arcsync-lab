# 智能查阅：所有账号共用一套界面

员工和管理员进入各自工作台的 #chat 视图，使用相同chat-panel.html、chat.js和chat.css。岗位只影响允许访问的导航与业务数据，不选择不同的聊天布局。默认收起对话记录，状态提示统一折叠。

## 防止已打开标签页混用新旧文件

- core/frontend.py为前端HTML、JavaScript、CSS和图标计算全局内容版本；所有账号使用同一个版本。
- 工作台和服务端渲染页面输出arcsync-ui-version元信息，CSS/JS地址携带相同?v=版本号；通用frontend-sync.js先于页面控制器执行。
- 延迟加载的聊天面板要求ui_version与服务端当前版本一致，否则409。响应也返回版本，客户端匹配后才挂载；不把新模板交给旧控制器。
- 旧版本资源请求拒绝混用。通用更新脚本不受此限制，确保启动期间资源变化也有恢复路径。
- 页面进入、切换和重新聚焦时检查版本；可见标签页每15秒复查。空闲页面自动重新载入并保留会话URL。
- 正在生成、输入尚未发送或表单尚未保存时暂缓重载，显示更新提示。保存成功会清理对应的未保存标记；不在本地存储业务文本。刷新循环有保护。

已经打开、且早于本机制上线的旧标签页尚无检测脚本，需要刷新一次才能获得自动更新能力。上线前控制器缺少版本参数时会被面板接口拒绝，不再拼出半新半旧的界面。新打开和之后更新的标签页不需要各用户手动清缓存。

## 验证

新增tests/test_frontend_versions.py，覆盖六种岗位的资源版本、公共聊天模板、旧版本拒绝、CSS更新版本变化、接口鉴权和旧入口跳转。浏览器使用复制前端和临时数据库复现“数据快照待更新 + 模型未配置”，验证默认折叠、空闲标签页自动更新、未发送输入保留及更新后继续进入同一会话地址。没有修改实际业务数据。
