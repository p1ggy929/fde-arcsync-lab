# 云州档案 MVP 量化测试方案

本方案用于验收公开档案查阅 MVP。以 34 项可复现检查覆盖正常、边界、对抗、权限和故障场景。测试使用三岗位演示账号、合成档案和独立 SQLite，按 HTTP 响应、页面提示与数据库状态联合判定。

## 范围和数据

测试基线为提交 798bd8d，独立回环端口 18766。用三个独立会话分别模拟业务查询代表、档案整理员和查阅审核员。

固定测试资料 YZ-CJ-1988-003，版本 v1.0，共 12 个扫描页，纸质起页为 25。用 YZ-R-1991-002 验证受限档号不可读。业务单以“核对规划更正范围”为用途。

对抗请求仅发送至隔离环境。上线环境的 HTTPS、负载、权限配置与真实资料准确性单独复验。

## 验收口径

执行率 = 已执行数 ÷ 34，门槛 100%。通过率 = 满足全部断言的用例数 ÷ 34，门槛 100%。HTTP 状态匹配和业务断言均通过才计为通过。

未经授权的业务写入数、受限内容返回数和未确认引用数的容许上限均为 0。任一项超出即阻断上线。

本机基准使用 4 并发、40 次检索。按从快到慢排序取第 38 个响应耗时作为 P95，门槛 500 ms。服务重启后 5 秒内应可正常访问，并读回一致状态、修订与引用。

## 场景覆盖

| 场景 | 数量 | 主要判定 |
| --- | ---: | --- |
| 正常 | 13 | 贯通三岗位流转，并抽样检索响应时间。 |
| 边界 | 7 | 核查搜索长度、扫描页范围和人工确认字段。 |
| 对抗 | 5 | 使用无害合成输入检查脚本转义和恶意表单拦截。 |
| 权限 | 5 | 覆盖匿名、受限资料、岗位写权限和伪造会话。 |
| 故障 | 4 | 检查异常提交、登录失败与本地服务重启恢复。 |

## 执行和记录

先启动独立实例，确认 /login 可达，再按正常闭环顺序准备业务。需要定位中状态的 B06 和 A05 在 N07 之前执行。F01 在 N03 之后执行，F02 在 N10 之前执行。

每项记录用例 ID、角色、操作与输入、实际 HTTP、业务断言、耗时和结论。保留关键页面截图，检查截图是否包含私密字段。

失败时保留原证据，登记复现步骤和影响。修复后复测原用例并重跑同类别，业务流转变更还要重跑正常闭环。上线验收须用目标版本和目标域名重跑。


## 复测启动

```sh
sh scripts/start.sh --check
MVP_QA_DIR=$(mktemp -d)
ARCSYNC_ENV=development ARCSYNC_DATABASE_URL='' \
ARCSYNC_DB="$MVP_QA_DIR/mvp.sqlite3" PYTHONPATH=src \
  .venv/bin/python -m uvicorn mvp.app:create_app --factory \
  --host 127.0.0.1 --port 18766 --no-proxy-headers
```

使用浏览器表单或 HTTP 客户端复测。正常 POST 表单使用 application/x-www-form-urlencoded 和 Origin: http://127.0.0.1:18766。每个岗位使用独立的会话。结束后停止临时实例。
